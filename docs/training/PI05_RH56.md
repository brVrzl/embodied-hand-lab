# π0.5 RH56 training integration

Embodied Lab contains the project-owned π0.5/RH56 training integration for the
audited physical bottle task. It includes the audited-data manifest and
LeRobot view builder, explicit 12-D arm-plus-RH56 repacking, language and image
transforms, train-only normalization, the official JAX LoRA configuration,
validation-loss checkpoint comparison, and the Thor supervisor/resume path.

The upstream OpenPI core is kept as the Git submodule
`third_party/openpi`, pinned by `experiments/pi05_rh56/openpi.lock.json`, and
mounted read-only into the Thor container. This keeps the upstream
license/update boundary clear while keeping all project-specific experiment
behavior in this repository.

## Verify the runtime

This is source and container inspection only. It does not connect to a robot:

```bash
experiments/pi05_rh56/scripts/check_openpi.sh
experiments/pi05_rh56/scripts/check_openpi.sh --require-image
```

The default checkout is `third_party/openpi`; override it with
`PI05_OPENPI_REPO` only when using a separately audited checkout. The expected
upstream commit, base model, backend, and container image are recorded in
`openpi.lock.json`.

## Training entry points

The training path is training-only and does not perform inference or robot
rollouts:

```bash
experiments/pi05_rh56/scripts/train_weekend.sh start
experiments/pi05_rh56/scripts/status.sh
experiments/pi05_rh56/scripts/train_weekend.sh stop
experiments/pi05_rh56/scripts/train_weekend.sh resume
```

The project adapter and staged checks are in
`experiments/pi05_rh56/scripts/openpi_runner.py`. Outputs, datasets, caches,
logs, and checkpoints stay under ignored `outputs/training/pi05_rh56/`.
The exact task, audited split, action semantics, image mapping, and known
limitations remain documented in `experiments/pi05_rh56/RUNBOOK.md`.

## Current boundary

The integration is offline/Thor training infrastructure, not a physical policy
validation claim. The native action contract remains six absolute JAKA targets
plus six absolute RH56 active-actuator targets. Force observations remain in
the source data but are not used by this baseline. No training command sends
movement commands to JAKA or RH56.

# π0.5 RH56 训练集成

Embodied Lab 已包含面向人工审核 physical bottle task 的项目专用
π0.5/RH56 训练集成，包括审核数据 manifest 和 LeRobot view、明确的 12 维
机械臂加 RH56 action repacking、语言和图像 transform、仅使用训练集的
normalization、官方 JAX LoRA 配置、checkpoint validation loss 比较以及
Thor 上的 supervisor/resume 路径。

OpenPI 上游核心代码作为 `third_party/openpi` Git submodule 保留，
由 `experiments/pi05_rh56/openpi.lock.json` 固定 commit，并以只读方式
挂载到 Thor 训练容器中。项目专用的实验代码和运行行为仍由本仓库维护。

检查 runtime：

```bash
experiments/pi05_rh56/scripts/check_openpi.sh
experiments/pi05_rh56/scripts/check_openpi.sh --require-image
```

默认 checkout 是 `third_party/openpi`，只有在使用另一个经过单独审计的
checkout 时才通过 `PI05_OPENPI_REPO` 覆盖。训练入口仍是：

```bash
experiments/pi05_rh56/scripts/train_weekend.sh start
experiments/pi05_rh56/scripts/status.sh
experiments/pi05_rh56/scripts/train_weekend.sh stop
experiments/pi05_rh56/scripts/train_weekend.sh resume
```

该集成只覆盖离线/Thor training infrastructure，不代表真机 policy
validation。native action contract 仍是六个绝对 JAKA target 加六个绝对
RH56 active-actuator target；baseline 不使用 force。训练命令不会向 JAKA
或 RH56 发送运动命令。
