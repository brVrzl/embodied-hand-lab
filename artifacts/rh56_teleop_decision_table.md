# RH56DFX teleoperation decision table

Evidence level: repository audit plus deterministic fake-backend tests. No
RH56 or JAKA hardware was started. Candidate rates are experiment ranges only;
they are not configuration defaults or recommendations to bypass safety.

## First hand-only hardware experiment recommendation

Keep all production rates and safety polling unchanged for the first experiment.
Run the existing hand-only gate with diagnostics enabled, exact duplicate
suppression enabled, and stale-command dropping disabled. Use a short bounded
duration and repeat a scripted sequence of hold, slow open/close, fast
open/close, and independent thumb/finger movements. Capture Quest receive,
retarget, submit/unique/coalesced, serial attempt/success, command age,
per-register latency, `ANGLE_ACT`, CURRENT, FORCE, STATUS, ERROR, and an external
video/time reference. Compare physical onset and settling with command and
`ANGLE_ACT`; do not infer physical bandwidth from JSONL row count. Only after
that evidence should options A, B, or E receive a separately authorized test.
